# 区域周报聚合与生命周期实施计划

用户已授权常规决策自行推进；本功能验证完成后单独提 PR 到 zy，不自动合并。基线8c1ab28，已备份。work_state 工具当前不可用，不使用其他内置待办替代。

## 数据与口径

沿用 care_events 的稳定事件ID、人物/模型/模式隔离与反馈表。v4增量新增 weekly_observations、weekly_policies、care_privacy，旧行不改写。每次查询从源数据计算，不保存周报派生缓存，因此撤销/过期/删除不会留下旧统计。

事件按开始时刻归属本地周（星期一0点）、四个6小时时段和声明的粗区域；跨周持续事件只计开始周一次。观测区间按周/时段切分并求并集，不依赖检测帧数。有效分钟样本=某分钟内有效观测至少30秒，默认本周与上周各达到30个样本才能给事件率趋势；阈值可设置。没有观测返回no_observations、空事件率和空趋势，不给任何风险评分或文字。

感知质量每行给有效时长比例、可用质量分数的时长加权均值和质量覆盖率；未知分数保持null，不能捏造1。人工确认只算未撤销且明确 confirmed=true 或 label=confirmed 的目标事件；false_alarm另计，撤销后回到未核验，原感知计数不删除。

默认UTC+08:00，可设置固定时区偏移（含半小时/45分钟），无外部时区数据库依赖；本版不支持夏令时。区域来自明确粗区域注册表，未知归unknown，不输出坐标。

## 生命周期与入口

周报数据默认保留90天，可设1..3650天；自动任务由真实Runtime检测/tick调度，默认每小时，时钟倒退或不合理时跳过并记录。只自动清理当前人物/模型/模式周报源及对应反馈/队列，保留当前活动事件；不在shadow清理live数据。

显式个人数据删除按API中的人物+模型覆盖两种模式、反馈审计、常态样本、事件、会话、队列、观测和策略；保留最小删除标记防止仍运行的检测自动重建。恢复采集必须显式请求。其他人物/模型不动。共享录像/人脸目录不由这个SQLite接口物理删除，避免误删其他人；这不等于全设备/云端擦除。

新增认证JSON周报、策略、删除/恢复接口，复用已有Bearer保护；不接入MaaS客户端、不生成周报文案。源观测由CareRuntime接真实调用点并保存有效间隔，重启不补算离线观测。新功能默认关闭，既有行为保持。
