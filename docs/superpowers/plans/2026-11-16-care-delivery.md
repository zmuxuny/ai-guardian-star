# 本地集成交付计划与初始缺口

基线：`2499d1d`，仅在 zy 工作和推送。用户授权补齐实现并仅做本机模拟验收，不连接设备、不发线上告警、不提交私有配置。

## 初始核对（修改前）

1. 未接通：ascend_board_server.inference_loop 只调用 AlertEpisodeTracker，未导入或调用 CareMachine/LocalCareStore。
2. 未接通：EventClipCache.trigger 在 event_id 缺省时调用 HistoryStore.add_event 生成 ID，但服务忽略其返回值；反馈模块没有事件索引校验、回写 API 或补传队列。
3. 未接通至实际服务：ShadowRunner 只有离线工具调用，未进入检测路径。现有服务不受影子影响，但这不等于已验证运行中的双通路隔离。
4. 无持久状态恢复、无事务反馈补传，既有模块单测不能证明五个集成场景。

## 实施决策

新增默认关闭的 CareRuntime 和认证本地 API；配置显式允许的稳定人物标识、模型版本和模式，不把跟踪框 ID 当成人物身份。真实入口调用可独立执行的处理函数；影子分支只写本地状态/报告，不触碰原 MQTT 或录像触发。live 明确启用后才允许新提醒进入独立主题的持久队列。现有告警开关和调用保持原样。

本地 care DB 增量 v3：事件、会话检查点、outbox，所有键和查询仍绑定人物及模型版本；兼容 v1/v2 旧数据，备份后增量建表。反馈与审计及补传消息同事务；目标 ID 从已保存事件读取，原发生时间不可由请求覆盖。消息 ID 含原事件 ID 和 revision，ACK 后标记完成，允许按幂等键重试。

状态机增加公开检查点恢复接口；重启时间不算可信坐姿，按未知输入冻结/120秒作废，恢复短间断保留计时、次数和事件 ID。更换模式/模型不混用检查点。

先写失败测试，再实现；测试阈值使用默认 30 分钟并由虚拟时间生成可信观测，不绕过状态机。录像测试只替换编码设备，用真实 HistoryStore/EventClipCache 证明同段关联。FastAPI 采用进程内客户端，不开网络端口。MQTT 仅用录制型替身。

交付：三项核对的前后证据、五场景预期/实际 JSON、部署包白名单和哈希、默认关闭配置、可执行部署与回退说明及板端勾选清单。上板及真实接收端不在本次验证范围，明确写出限制。回退基线 `2499d1d`，数据库保留一致性备份，不用旧程序直接打开新结构。

work_state 工具当前不可用，不使用替代内置待办。实现后独立审查、全套回归、只暂存相关文件并推送 zy。

## 交付验证结果

三项接通核对及前后证据见 docs/care-delivery-evidence.md；板端/API侧已接通，真实App侧未接通并已向Jianyuanxi提出 issue #25。检测输入仍为静止代理，不能把本机模拟当作真实坐姿验收，live不在本次准入范围。

五个指定集成场景均通过并导出 expected/actual：短重启恢复同ID及计时、重复反馈一行、软撤销、断网重启原幂等键补传、多事件共用一个真实录像索引。使用默认1800秒阈值和真实旧tracker/状态机/SQLite/缓存，只替换编码设备与发送接收端。初始测试的空new_events已替换为真实旧tracker计算，保留了同一套输入数据及阈值。

冻结回归：251项，0失败，18项设备/MQTT环境跳过。15项集成检查与4项安装/回退检查包含长间断换ID、tick录像、事务失败回滚、错误模型/人物/凭据、私有配置拒绝、v2到v3不改旧数据、基线漂移拒绝和回退保留新数据。故障注入产生的recording_failed日志为预期，不是未处理失败。

独立审查发现并修复三项真实缺陷：内部reset后旧事件ID复用、tick播报没有录像关联、安装结束重写回退清单可截断；均先有失败证据再修复，复核无新阻断项。额外隔离录像IO异常，保留已提交状态与原ID，避免退回另一UUID。

部署工具仅白名单文件，基线2499d1d哈希不符则停止；私有SQLite备份与代码备份先于替换。prepared回退清单不再重写，rollback保留新DB，禁止直接数据库降级。真实设备、MP4、实际接收端及App均未认证，板端清单未预先勾选。OpenWolf命令不可用，已尝试扫描，辅助索引未更新。
