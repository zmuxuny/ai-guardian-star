# 久坐关怀状态机与模拟验收

实现：`src/sedentary_care.py`；场景：`tools/run_sedentary_scenarios.py`；专项断言：`test_sedentary_care.py`、`test_sedentary_scenarios.py`。只依赖 Python 3.11+ 标准库，不调用真实传感器、音频或外部服务。既有板端以人体框持续静止近似判断久坐，本次没有修改或接入该链路。

## 一键运行与输出

```powershell
python3.11 tools/run_sedentary_scenarios.py --output .tmp/sedentary-scenarios.json
python3.11 -m unittest test_sedentary_care test_sedentary_scenarios -v
```

安装环境若使用 `python` 命令，可将 `python3.11` 替换为 `python`。第一条命令执行全部场景、校验断言、向终端输出完整 JSON，并另存 UTF-8 文件；失败退出码为 1，仍保存失败场景已有轨迹。第二条运行专项单元测试。所有时间均为虚拟时间，无真实等待。普通 `python -m unittest discover -v` 也会发现这两个根目录测试文件。

每个场景输出 `name`、`passed`、`error`、`checks`、`snapshot`、`transitions`、`broadcasts`。每条实际应播报记录包含 `at`（模拟开始后秒数）、带时区 `wall_time`、`level`、`text_id` 和完整 `text`。抑制/取消提醒只记录决策，不冒充播报。每条事件（包括无动作、自迁移和超时）都有前后状态、时刻、决策及快照。

快照可查坐姿累计秒数、下一提醒/冷却剩余秒数、暂停秒数及原因、当前级别、待提醒级别和各级已用次数。`export()` 返回独立副本，可直接 JSON 序列化。历史记录按整个状态机实例保留，业务复位不删除历史；长期接入时由调用方管理实例和输出归档。

## 状态与输入分层

单个实例服务一个人的连续监护过程。调用方负责目标关联；发现换人必须发送 TARGET_CHANGED，不能将另一人的坐姿直接续接旧计时。

提醒阶段 `phase`：IDLE（未坐）、SITTING（累计）、L0、L1、ACK（回应冷却）、EXHAUSTED（次数用尽或本轮拒绝）。输入可靠性独立保存：可信或 PAUSED。暂停时保留原 phase，因此可以同时表达“已提醒 L0，目前因设备故障暂停”。对外 `state` 在不可靠时为 PAUSED，否则等于 phase。

完整输入事件：

- SIT：可信坐下或持续坐姿，刷新观测有效期。
- STAND：可信起身。NON_SIT：可信行走、躺下等非坐姿；本模块只累计坐姿，不判断睡眠/卧床风险。
- OCCLUDE：遮挡；LOW_CONFIDENCE：低置信度或姿态冲突；MISSING：缺帧/缺失检测；TARGET_LOST：目标离开画面或跟踪丢失；DEVICE_ERROR：采集/检测故障。这五类分别记录原因，统一进入 PAUSED，不能推断已经起身。
- TARGET_CHANGED：换人或无法继续关联原目标，清空旧轮，等待新可信输入。
- RESPOND：明确回应；DEFER：明确要求稍后提醒；DECLINE：明确拒绝本轮后续提醒，不能将“未回应”推断为拒绝。
- TIMEOUT：调用方通知虚拟时间已推进；引擎将其拆解为 observation_timeout（观测失效）、uncertainty_expired（不可靠期满）、reminder_timeout（提醒到期）、ack_timeout（回应冷却到期）或 pending_released（待提醒释放），保留原因和准确时刻。

## 完整状态迁移表

| state / phase | SIT | STAND / NON_SIT / TARGET_CHANGED | OCCLUDE / LOW_CONFIDENCE / MISSING / TARGET_LOST / DEVICE_ERROR | RESPOND / DEFER | DECLINE | TIMEOUT |
|---|---|---|---|---|---|---|
| IDLE | SITTING，从零开始 | IDLE，清空 | PAUSED，保存 IDLE | IDLE，记录无动作 | IDLE，记录无动作 | IDLE，记录无动作 |
| SITTING | 保持，刷新观测 | IDLE，清空 | PAUSED，冻结 SITTING | 有待 L0 则 ACK 并取消待提醒；否则保持 | EXHAUSTED，取消后续提醒 | 到期 L0，或静默抑制；观测失效则 PAUSED |
| L0 | 保持，刷新观测 | IDLE，清空 | PAUSED，冻结 L0 | ACK，取消待提醒，开始冷却 | EXHAUSTED，取消后续提醒 | 到期 L1，或静默抑制；观测失效则 PAUSED |
| L1 | 保持，刷新观测 | IDLE，清空 | PAUSED，冻结 L1 | ACK，取消待提醒，开始冷却 | EXHAUSTED，取消后续提醒 | 到期重复 L1，达上限 EXHAUSTED；静默则抑制；观测失效则 PAUSED |
| ACK | 保持，刷新观测 | IDLE，清空 | PAUSED，冻结 ACK | 保持，不延长冷却 | EXHAUSTED，取消后续提醒 | 冷却到期播下一条尚未发送的级别（L0 或 L1），静默则抑制；观测失效则 PAUSED |
| EXHAUSTED | 保持，刷新观测 | IDLE，清空 | PAUSED，冻结 EXHAUSTED | 保持，不恢复次数 | 保持 | 无提醒；观测失效则 PAUSED |
| PAUSED（任意保存 phase） | 未满 120 秒恢复保存 phase；满则新轮 SITTING | IDLE，清空 | 保持，更新原因但不延长连续不可靠期限 | 保存 phase 为 L0/L1 或有待提醒时改 ACK，其余保持；不恢复可靠性 | 保存 phase 非 IDLE 则改 EXHAUSTED；仍暂停 | 未满期限保持；满则 IDLE，清空，无播报 |

## 计时与提醒规则

所有阈值可通过 Config 配置并校验，以下默认值是工程策略，不是医学标准。

1. 首个可信 SIT 开始累计；连续 SIT 只刷新观测，不重置累计值。可信 STAND/NON_SIT 或 TARGET_CHANGED 立即清空本轮计时、级别、次数、冷却和待提醒。
2. 可信坐姿输入有效期为 30 秒。没有新观测时，TIMEOUT 会在最后可信 SIT 后满 30 秒自动进入 PAUSED，原因 observation_timeout。不能仅推进 30 分钟就假设用户一直坐着；场景的 hold 明确生成周期可信 SIT。
3. 不可靠期间冻结坐姿时间、升级间隔、重复间隔和回应冷却，不播报。连续不可靠满 120 秒清空本轮；用户已确认遮挡按此处理，其余异常采用相同默认期限。重复异常或异常原因切换都不能延长期限。短暂停后恢复可信 SIT，继续冻结前剩余时间。恰在满 120 秒时恢复，旧轮先失效，再开始新轮。
4. 累计可信坐姿满 1800 秒播 L0。其后忽略满 300 秒播首次 L1；再忽略满 300 秒播第二次 L1。默认本轮最多 L0 一次、L1 两次，共三次。达到上限进入 EXHAUSTED；`max_l1` 可配置，L0 固定每轮最多一次。
5. L0/L1 或存在待提醒时，RESPOND/DEFER 取消待提醒并进入 ACK，冷却 600 秒可信坐姿时间。重复回应不续期；遮挡时回应不代表姿态可信，冷却保持冻结。冷却后，若 L0 尚未实际发送则先 L0，否则继续尚有次数的 L1。回应不清坐姿累计、不恢复已用次数。提醒未到且没有待提醒时的提前回应只记录。
6. DECLINE 在活动轮内取消后续提醒，进入 EXHAUSTED；没有活动轮则无动作。起身、换人或不可靠期满可结束这一轮。
7. 级别只反映最后实际播报：此前未播报为 null；ACK/PAUSED 保留最后级别；最后一次 L1 后虽 state 为 EXHAUSTED，level 仍为 L1。待提醒的级别单独在 pending_level，不能当作已经播报。

L0 文案：`sedentary.l0` — 已经坐了一会儿，方便的话起来活动一下吧。

L1 文案：`sedentary.l1` — 您已连续久坐，建议现在起身走动、舒展一下。

## 静默与边界顺序

默认每天 [22:00, 次日 07:00)，包含起点、不包含终点。支持白天静默窗口、跨午夜窗口和完全关闭静默；起止相同或只设置一端会明确报错。使用显式固定时区墙钟，默认 UTC+8；不支持夏令时或运行中墙钟跳变。

- 到期提醒若在静默内，写 suppressed 轨迹、保留一个待提醒项，不调用播报接口、不耗次数、不开始下一次升级。长静默不会把尚未播出的 L0 直接升级为 L1，也不会积累多条补发队列。
- 静默结束且可信坐姿时，立即释放这一条提醒，下一次间隔从实际播报时刻开始。起身、换人、拒绝、回应按各自事件规则取消待提醒。若仍暂停，等待可信恢复后重查；满 120 秒则本轮和待提醒一起作废。
- 恰在 22:00 到期抑制；恰在 07:00 到期可播报。静默边界通过带时区时间计算，不依赖每秒轮询。
- handle(event) 先按准确时刻重放严格早于当前时刻的截止项，再处理当前外部事件，最后处理等于该时刻的截止项。因此同刻起身、回应或异常输入先于提醒；同刻 SIT 可以刷新有效期。若调用方先发送 TIMEOUT，再发送同刻 STAND，则尊重调用顺序，不撤回已输出记录。
- 同刻“观测失效”和“提醒到期”由观测失效优先，不能对失效坐姿播报。不可靠满 120 秒与恢复同刻则先废弃旧轮。一次大步推进会依次重放截止项，与相同输入下的小步推进一致。
- 虚拟时钟禁止倒退和非有限数值。未知输入在处理任何到期项前报错，不能吞掉事件或修改已有状态。引擎无后台任务，调用方必须在时间推进后调用 handle(TIMEOUT) 或提供其他事件。

## 场景覆盖

场景运行器覆盖默认 L0/L1 精确触发点、重复间隔和上限、起身复位、五类异常的冻结/恢复/失效、119/120/121 秒边界、无观测超时、同刻事件顺序、回应/稍后/拒绝、换人和非坐姿、静默起止前后及恰好边界、跨午夜/跨日、白天静默、静默中取消或暂停、L1 顺延与避免补发洪峰。专项测试另外验证非法输入/配置、JSON 独立副本、大小时间步长等价，以及完整状态事件组合。

## 接入边界

本次交付离线模块和验证工具，不代表真实坐姿模型、目标跟踪、设备链路或真实音频已验收。调用方负责可信度判定、目标标识和周期 TIMEOUT 调度；模拟播报接口只追加记录，没有音频输出。可通过注入具有 now / wall_at(seconds) 的时钟使用该状态机；需要在应用重启后续接状态时，应另行设计持久化与时钟恢复。
