# 规则与语言模型隔离原型试验

范围：用户已同意先尝试 1.5B 模型、固定话术、业务边界、新样本与延迟改进。本轮只做独立文字原型，不接生产反馈接口、事件存储、报警、音频或 App，不冻结跨端协议。

## 冻结策略

- greeting 根据固定原因代码返回固定问候，不插入模型生成的天气、诊断或行动承诺。
- 对明确求助、有限的完整正向短句、转述和控制指令使用公开规则。有限短句以外不由模型单独确认 okay；模型建议 okay 转为 unclear。所有结果均 preserve_alert=true、auto_cancel=false。
- 可通过回调先发固定确认话术，再等待可选模型工作；这只验证程序事件顺序，不证明真实屏幕、扬声器或人感知的即时回应。
- 模型只连接显式回环地址，使用有截止时间的 SSE 请求，区分首个非空内容和完整结果时间；只有 stop+[DONE]+合法 intent 才返回结果，截断/超时/异常回退固定话术。
- 规则无法覆盖任意否定、转述和混合表达，必须统计漏判、误报和保守弃权；不把保留告警或回退视为模型答对。

## 执行步骤与验证

1. 先写开发用边界与网络故障测试，确认缺模块失败，再实现独立 tools/local_care_prototype.py；不改 src。单元测试覆盖状态不关闭、明确求助不等模型、指令/转述、超时、截断、重复 JSON、首内容时刻与回环限制。
2. 本地通过后提交冻结策略和代码。随后新增合成评估集并记录 SHA-256，再提交冻结。评估集生成后，不按其模型结果调整策略或提示；若发现代码缺陷，需要另标一次试验，不能覆写原结果。
3. 样本由同一作者生成，并非第三方盲测。与上一轮 20 条不同，只能称“策略冻结后新增、未据运行结果调参的合成集”；预期标签单独存储，不放进模型请求。
4. 复用现有已校验 CPU 运行时和 1.5B 权重，在新目录和回环端口试验。先记录原服务/配置与文件指纹及摄像头基线，校验新复制代码，在原板 Python3.9.2 运行相关测试。
5. 对同一新样本分别执行裸模型与受约束原型，分别报告语义正确数、明确求助漏判、错误 okay、unclear 弃权、规则来源/模型调用比例。规则跳过模型的案例不能计成模型正确。
6. 测量进程就绪、首次分类、同前缀后续分类、主动预热后的请求、不同前缀切换，记录实际 SSE 首内容和完整时间。模型不重启的请求不能称整机冷启动；预热成本单列。演示模型断开、极短截止时间与输出异常回退。
7. 监测原相机、模式、内存和进程；试验结束停止自己启动的进程，检查端口关闭、原文件指纹及服务单元不变、相机和 JPEG。保存原始合成结果和脱敏报告，更新本方协作记录，只有本地提交。

## 判定边界

通过单元测试只证明代码边界；原型减少错误 okay 可能同时增加无法判断，不等于理解能力提升。任何统计必须保留原始分母和原模型错误。流式首内容是 JSON 片段，不能直接播给老人；可供业务使用的意图仍须等完整校验后产生。

本轮结果不能代替真实语音、老人体验、正式反馈协议、长期运行或关怀功能验收。
