## 个性化模块（gufeng）

### 最后要做到

1. **有作息数据**：每隔一段时间记一条“几点、在哪个区域、什么状态（站 / 坐 / 躺 / 不在）”。
   - 开始阶段用自己写的脚本造几周的假数据；后期请 zhouyang 在开发板上接一个记录点，换成真实数据。
2. **知道“平时什么样”**：根据历史数据算出简单的规律，比如平时几点起床、几点睡、白天大概活动多久。用平均值、范围这类简单统计就够了。
3. **发现反常**：至少做 2～3 条规则，比如：
   - 到点很久还没起床；
   - 白天很长时间没有活动；
   - 夜里在卫生间待太久。

   提醒里要带一句理由，比如“平时 7 点前起床，今天 8 点半还在床上”。同一件事不要反复提醒。
4. **提醒能发出去**：发现反常后，通过现有的 MQTT 告警发到 App，App 能收到并显示。
5. **能演示**：准备一份带异常的数据，跑一遍能看到提醒被触发。

### 自己决定

数据怎么存、怎么造假数据、规律怎么算、阈值定多少、代码怎么组织。动手前先写几句思路给大家看看。

## 本地模型（zhouyang）

### 最后要做到

1. **先试跑**（12 月底前）：在开发板上试 1～2 个小模型，记下回答速度、内存占用，以及和检测服务一起开时会不会卡。写几行结论：板子上能用，还是只能放到云端。
2. **能对话**：在开发板上用文字（能接上语音更好）和模型简单聊天，断网也能用。回答速度在能接受的范围内就行。
3. **能问一句、听一句**：收到个性化模块发来的提醒时，用模型生成一句问候，比如“您今天起得有点晚，身体还好吗？”；老人回答后，能大致分辨“没事”还是“需要帮助”。
4. **出问题有兜底**：模型太慢或报错时，改用固定的问候话术，流程不能卡住。
5. **能演示**：录一段视频，内容是拔掉网线后完成一次问答。

如果板子确实跑不动，就改用云端模型完成第 2～4 条，在试跑结论里写清楚原因。

### 自己决定

选什么模型、用什么方式在板子上跑、提示词怎么写、语音怎么接。

## 两人对接

第一周一起定一份简单的消息格式，写成文档放进 `docs/`：

- 个性化模块发出：提醒类型、时间、理由。
- 本地模型回传：老人回答的大致意思（没事 / 需要帮助 / 没听清）。

格式定好后，gufeng 可以先用固定话术把提醒流程跑通，zhouyang 可以先用假提醒调问候话术，互不等待。
