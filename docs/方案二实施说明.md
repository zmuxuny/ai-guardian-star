## 2. 本次完成的内容

### 2.1 服务生命周期和资源释放

修改 `src/ascend_board_server.py`：

- 为 UDP、音频、推理线程保存线程对象，便于统一管理。
- 为音频广播任务保存 asyncio task，并在服务关闭时取消。
- 关闭服务时依次停止推理、音频、UDP socket 和后台任务。
- 增加音频模块不可用时的兼容 stub，避免导入失败直接阻断服务清理。
- 将脚本入口放到所有路由定义之后，确保人脸 API 在 `python3 src/ascend_board_server.py` 启动时已经注册。

### 2.2 人脸管理接口

人脸接口仍然位于 `src/ascend_board_server.py`，但现在默认关闭，必须在开发板环境变量中配置管理员令牌：

```bash
export AI_GUARDIAN_FACE_ADMIN_TOKEN='请在设备上设置随机长令牌'
```

客户端通过请求头提交：

```text
X-Admin-Token: <设备上的管理员令牌>
```

接口行为：

- `POST /api/face/enroll`：上传并规范化图片，写入人脸目录和 SQLite。
- `DELETE /api/face/{user_id}`：删除对应数据库记录和图片。
- `GET /api/face/list`：列出已登记人员。

增加的保护包括：

- 管理员令牌验证。
- `user_id` 字符限制，阻止路径穿越。
- `name` 目录名校验。
- 单个上传文件最大 8 MiB。
- 图片格式和可解码性检查。
- 图片像素数量限制。
- 数据库写入失败时删除已保存的图片。
- 同一 `user_id` 重复录入时清理旧样本。
- 删除操作先暂存图片，数据库删除失败时尝试恢复。

数据库路径默认为 `/root/ai_guardian/db/guardian.db`，也可以通过以下变量覆盖：

```bash
export AI_GUARDIAN_DB_PATH='/实际/数据库路径/guardian.db'
```

### 2.3 音频服务

修改 `src/ascend_voice_stream.py`：

- 增加清理锁，避免音频线程和服务关闭流程同时释放 PyAudio 资源。
- 停止音频时先停止活动流，再关闭流并终止 PyAudio。
- 保留原有 USB、默认设备和板载耳机后备选择逻辑。

`src/ascend_audio_output.py` 继续作为板载耳机后备输出实现。它依赖同目录的 `libguardian_audio.so`，该动态库必须使用与开发板匹配的构建版本，目前没有放入仓库。

## 5. 开发板部署建议

在开发板上进入仓库根目录后：

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
python3 -m pip install -r requirements-edge.txt
export AI_GUARDIAN_FACE_ADMIN_TOKEN='设备本地随机令牌'
python3 src/ascend_board_server.py
```

建议按以下顺序验证：

1. 打开 `http://<开发板IP>:5000/`，确认网页能加载。
2. 确认 `/api/stats` 返回状态数据。
3. 确认 `/video_feed` 能持续输出摄像头画面。
4. 在浏览器发起对讲，确认麦克风上传和开发板播放均正常。
5. 使用 `X-Admin-Token` 测试人脸列表、录入和删除。
6. 用可控动作测试跌倒、久坐和陌生人告警。
7. 记录开发板型号、CANN 版本、模型文件、音频设备名称和验证结果。
