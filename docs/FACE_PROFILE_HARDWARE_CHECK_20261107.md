## 改动及边界

1. 有检测器支持、图像质量合格的侧脸仍进入特征匹配；匹配通过原有分数和身份间隔要求后，仍可确认姓名。
2. 不满足正脸关键点门禁的样本，低匹配分数不再进入陌生人投票，并清除之前尚未确认的负票。它会显示 `Face:unverified`（接口仍为 `pending`，原因 `pose_unverified`）。不把原有姓名无限保留给后续可能换人的轨迹。
3. 没有可用人脸/关键点、模糊、侧向等情况等到超时，只表示身份未确认，不再把超时当作陌生人证据。仍继续采样；新的成功匹配可恢复姓名。
4. 真实、可用、满足正脸门禁的多次明确不匹配仍可确认陌生人；新证据会清除旧超时标记。未登记人物不会因为本次改动自动获得某个已登记姓名。
5. 登记照片补充紧裁剪模板（与实时检测器框的尺度一致）及水平镜像视图，降低取景尺度和镜像方向不一致的影响；完全对称的重复镜像不增加模板。最多约8个视图/张，登记照片计数仍按原始文件计数。图库构建/热加载时间及内存可能增加，实时识别仍只提取一次特征。
6. 镜像不是合成侧脸，不能从一张正脸恢复被遮住的五官。需要同一人真实的正脸、左侧、右侧照片。现有录入接口同一身份追加不同照片；验证时检查照片数确实增加，不要建立三个不同姓名。
7. ArcFace匹配阈值、不同身份间隔、图像质量门禁、空图库及模型故障处理均保留。正脸门禁仍是现有关键点几何启发式，并非经过标定的3D头姿估计，实际角度边界必须上板验证。

## 真人验证矩阵

准备至少两位已登记人员A/B，以及未登记人员C；库中A/B各有真实正脸、左右侧脸样本。保持与基线相同的光照、距离、模型和阈值。原始人脸照片、视频和姓名只保存在获授权的私有测试环境，不入仓库。

| 场景 | 需要检查的结果 |
|---|---|
| A、B分别正脸及左右约30°、45°，各重复5轮 | 记录正确身份率和首次确认耗时，不能把pending/unverified算作识别成功 |
| 已知人员转到大角度、背脸、被遮挡，再转回正脸 | 不因坏样本或等待超时直接报陌生人；转回后能重新确认 |
| C分别正脸、左右侧脸 | C不能被错认成A/B；正脸的有效明确非匹配仍能触发陌生人判定 |
| A与B同框、相互走过，随后C进入A原位置 | 不串人、不凭原轨迹永久保留姓名；出现同名竞争时等待重新确认 |
| 图库为空、图库重载失败、识别模型故障 | 继续保持既有失效处理，不凭不可用分数确认陌生人或姓名 |
| 两人同框、连续运行和图库重建 | 记录识别延迟、推理帧率、热加载耗时及内存，确认新增图库视图没有拖慢硬件 |

分别报告：正确身份率、未确认率、已知人误报陌生人的轮数、未登记人被误认成已知人的轮数、首次身份确认耗时。减少误报警不等于提高了真实身份识别率；如果侧脸长期停在unverified，该角度的识别仍不算通过，需要补真实样本或评估检测/识别模型。
