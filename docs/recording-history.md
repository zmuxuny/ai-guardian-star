# 最近 24 小时录像回放

## 行为

- 打开记录页/刷新时确定查看时间；三个筛选共享该时间，不随切换标签漂移。
- 全部：显示 `[查看时间−24小时, 查看时间]` 内所有已完成、可用的录像片段，按时间正序播放，结束后自动播放下一段。
- 摔倒/久坐：服务器记录首次检测到对应状态的时间，收到正常/其他状态后确定结束；保留开始前 60 秒至结束后 60 秒，裁到上述 24 小时窗口。重叠事件范围合并。
- 持续事件保留检测到的全程。尚无明确结束信号的区间标为“结束时间待确认”；告警消息间隔超过 30 秒时不推断其后仍持续，采用最后一次确认时间。不会用 App 的展示超时冒充真实恢复时间。
- 后端独立记录 MQTT 事件，App 不在线也能留下事件和录像。手机只缓存当前播放的一个片段，切换/离开页面时清除。
- 未录制、断线、服务启动前、过期录像不会被伪造成完整 24 小时覆盖。正常首段需要约 1 分钟完成后才能回放。

## 服务组成

- `recording_store.py`：独立 SQLite 索引及滚动清理，默认 `/var/lib/guardian-recordings/`。
- `deploy/recording_worker.py`：从服务器回环的开发板 MJPEG `/video_feed` 接收真实帧，输出每段约 60 秒、640 宽保持原比例、8 FPS、H.264 MP4，无音频。断线重连，损坏/未完成文件不加入索引。
- `guardian_mqtt_plugin.py`：只索引已认证 `ascend_board` 发到固定告警主题的消息；不记录原始载荷、不修改现有鉴权规则。
- `recording_api.py`：复用登录会话和设备账号 allowlist。POST `/api/recordings/query` 查询；POST `/api/recordings/media` 返回鉴权后的 MP4 二进制。无公开录像 URL、无查询串 Token。边界片段按请求范围裁切后发送，无法拖出事件范围观看其他时段。
- App `RecordingBrowser.ets`：底栏记录页使用该浏览/回放组件；个人中心重复的历史记录入口已移除。旧 `HealthHistory.ets` 及其事件 CSV 导出代码保留兼容，但不代表当前个人页仍有入口；CSV 内容为手机已接收的事件记录，不是录像导出。

## 运行边界

- 当前单开发板部署，获准访问该设备的账号共享其录像；多家庭多设备需要先补充服务端设备绑定与独立存储，不能直接扩展 allowlist 代替设备隔离。
- 512 kbps 目标视频码率约 5.5 GB/天，上限和实际大小取决于画面；剩余磁盘低于 2 GB 暂停新录制，不删除其他业务文件。
- 保留与窗口按毫秒计算；跨 24 小时边界的存储分段最多额外保留约一分钟，接口始终裁掉窗口外内容。裁切临时文件 15 分钟过期。
- 按段重连会有短暂采集间隔；缺口真实展示。当前检测事件的开始是服务器首次收到检测状态，不是算法尚未发现前的真实发病/跌倒起点。
- FFmpeg 与 ffprobe 单独安装在 `/opt/guardian-ffmpeg/bin/`，不替换系统程序。构建需具备 libx264；下载校验发行包 SHA-256。
- systemd：`guardian-recording.service`，内存上限 180 MB，CPU 上限 75%。启动无需摄像头在线；无视频时保持等待。

## 部署与回滚

1. 比较当前服务器 API、MQTT 插件与本地修改前版本的哈希。存在漂移时停止直接覆盖。
2. 备份 API、MQTT 插件、服务配置；使用 SQLite 在线备份保存现有账号数据库。
3. 安装新增模块、独立视频工具、录像 unit；先检查 Python 语法、unit，再重启 API/MQTT 并启用录像服务。
4. 检查原 `/health`、匿名录像请求被拒绝、现有登录会话中的三种筛选以及无视频空状态。摄像头未接入时不能宣称真实录制、事件裁切或视频播放验收通过。
5. 回滚时停止/禁用录像服务，恢复备份的 API 和 MQTT 插件并重启；保留账号数据库和新产生的录像，不用旧数据库覆盖业务数据。新增录像模块可留在原处，旧代码不会调用。
