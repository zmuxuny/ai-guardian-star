# 板端回放反馈与个人常态：首版运行说明

本轮仅实现板端；App、云端和真实反馈回传由 Issue #25 跟进。默认关闭新增采集，不改变跌倒判定、线上告警或确认时间。

## 开关与版本

在现有私有关怀配置中，保留原人物/模型/模式/数据库等设置，新增：

```json
{"personal_baseline_enabled": true, "camera_revision": "camera-position-001"}
```

这只是新增字段示例，不能替换完整配置。启用前先按现有交付规则备份、原板编译和隔离shadow验收；本轮没有推送、部署或启动设备。
`personal_baseline_enabled` 默认false；整体care为off时不初始化采集线程。关闭采集后仍处理已存反馈的撤销/恢复，防止再启用时旧样本复活。
camera_revision 必须在摄像头移动、视角或安装位置改变后更新。缺省可保存事件质量诊断，不生成可用个人样本或降级建议。模型版本来自实际配置，不能随意填一个新字符串冒充真实模型登记。
posture_v1 固定采用肩/髋四关键点置信度>0.4，归一化躯干倾角、检测框内髋高、框宽高比、粗区域与UTC+8的4小时时段。触边、无效或低质量输入只记质量原因。

## 事件与反馈

shadow下，原录像入口先创建事件，采集器接收它的原event_id，不另建可反馈的影子ID。live沿用既有care事件引用；新增采集不触发录像、播报或MQTT。
真实录像不可用或没有返回事件ID时跳过该事件，不按时间或片段ID猜测关联。身份未知、多人或低置信输入不进入个人库。
内部检测入口传入实际frame_shape，不改旧alerts对象、不修改姿态检测器或NPU/摄像头配置。
反馈沿用现有认证API：`POST /api/care/{model_version}/{person_id}/events/{event_id}/feedback`。

```json
{"payload":{"feedback":"untrusted","reason":"sitting_or_lying"}}
```

只有fall事件、有效特征且人物和摄像头版本明确时，`trusted`产生风险正样本；`untrusted`且原因为`not_fall`/`sitting_or_lying`产生正常样本。`uncertain`、错认人物、遮挡、画质不佳、其他或缺原因都不进入正常样本。
修改使用原ID。`operation=revoke`软撤销，`operation=restore`显式恢复；反馈重提不会偷偷恢复已撤销样本。反馈、审计、派生资格共事务；先反馈后采到特征也读取最新有效状态。
历史任意payload仍可读取；不符合新契约的旧反馈不会自动变成样本。采集关闭期间，通过既有事件反馈API修改同样会更新旧派生样本资格。
板端Bearer管理凭据只从私有配置读取；App不得硬编码，账号代理授权仍待#25完成。

## 本地基线和报告

唯一可靠已知人物、无原始跌倒候选、无已确认跌倒、无久坐或陌生人告警时，每秒至多一个观测。只保留按日/粗区域/时段的三个固定边际直方图，不留逐帧姿态、坐标或图像。
写入队列上限32；队列满丢弃新增观测并增加诊断计数，错误不包含原始特征或异常私有文本。
检测/无人轮询使用非等待的关怀锁与SQLite连接：后台采集正在持有写入资源时，立即跳过这一帧的附加关怀处理，原录像和告警继续；下一帧恢复。此取舍可能推迟关怀计时更新，避免新增存储任务拖住原告警。当前人物数仍刷新，不能借用上一帧的单人身份。
无人时tick按小时调度清理；关掉新增采集后，运行中的关怀实例同样维护旧数据保留期，重启后首次维护会补清理。整体care为off、进程未运行时不会启动额外维护线程，恢复运行后清理。
正常关停等待排空；超时返回False且服务记录`private_writer_shutdown_incomplete`，允许显式再次close重试，不能把超时当已保存。突发崩溃可能损失尚未落库的观测。

同一认证下读取：`GET /api/care/{model_version}/{person_id}/personal-baseline`。禁用返回503，错域404，未授权401。
报告只返回版本、有效正负样本数、事件数、质量/保护原因计数和直方图观测总数，不返回特征、分箱内容、逐事件ID或关键点。

- `assessment=confirmed_event_static_suggestion`：对已确认事件的静态建议，不能叫作实测减少误报或证明召回不降。
- `would_extend_confirmation_events`：同人物/模型/模式/相机/特征版本、同区域/时段，至少3个不同正常事件足够接近，且无接近的风险正样本和保护条件的建议数。
- 当前事件不能作为自己的正常训练样本；可信事件自身也参与正样本保护。反馈撤销后每次报告都会按当前样本资格重新计算。
- 首版阈值为倾角差<=10度、髋高差<=0.1、框比相对差<=15%，版本`personal_shadow_v1`。这些是待校验的建议参数，不是已有实机效果证据。
- 倒地长静止、无人回应、雷达跌倒三条件必须各自明确False才可能放行；未知和not_available都拒绝建议。当前真实检测链路未提供完整三项证据，因此真实建议数预计为0，应结合`protection_reasons`解释。
- 已确认反馈与常态直方图用于积累证据；直方图本身不能当成人工正常样本。匹配不足、缺配置、样本超上限均保守不建议。
- 报告最多评估最近1000个保留期内事件；`truncated=true`明确标注截断。有效样本超过256个时`samples_capped=true`，拒绝建议，避免截掉正样本后错误放宽。

测试中的完整保护条件是合成输入，只证明逻辑。未经完整候选时序回放，不能把静态建议数称为实际少报数。400跌倒+100站立回归集仍未作为本轮资产引入，正式启用门槛保持原Issue要求。

## 保留、删除和回退

schema5增量迁移；升级前自动保留SQLite一致性备份。原反馈、样本和审计保持原值，不覆盖旧数据库。
新特征/派生样本随所属事件的原保留策略清理，直方图按日清理；读取也限定当前有效保留窗口。旧模型/相机记录不会混入当前库的比较。
沿用已认证的人物数据删除接口：等待当前写操作完成，移除该人物排队特征与线程局部快照，删除三个新表对应作用域的数据，停用采集并使在途写入失效；显式resume后才允许新采集。备份仍遵守原独立保留政策，不宣称在线删除已擦除历史备份。
只回退代码不能让旧版程序打开schema5原库；禁止用旧备份覆盖新反馈。旧程序需使用升级前库副本的独立路径，schema5库保留供前向恢复。
既有source release、flat overlay和离线验证kit已补齐3个新增模块与迁移005；老flat工具只适用于其原先的初始化/指纹约束，不能用它覆盖已部署的不同版本。当前设备后续发布仍需私有指纹核对、最小补丁与独立回退包。

## 验证边界

专项覆盖事件ID接线、反馈撤销/恢复及乱序、事务失败回滚、迁移备份、隔离、直方图节流、未知保护拒绝、队列满/故障、删除及关停、认证聚合和打包完整性。
实际HistoryStore/EventClipCache在本机验证了原ID链路；本项未运行编码设备或证明真实MP4播放。未完成真人姿态准确率、真实App反馈、原板新代码编译/运行、现场身份专项和长期运行；不得标记为全端验收或正式个体适应上线。
