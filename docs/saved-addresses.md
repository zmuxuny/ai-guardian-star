# 常用地址

入口：个人 → 常用地址。

## 当前功能

- 页面仅保留保存详细地址和设为默认住处两类操作，每个登录账号最多保存20个住处。
- 表单仅填写详细地址（5–300字）并选择设为默认住处。不再显示住处名称、经纬度输入或坐标信息；列表不再提供编辑、删除按钮。
- 第一个地址自动成为默认，默认开关显示开启并暂不可关闭；之后可在列表中将其他地址设为默认。
- 默认开关下方不展示说明文字和取消/保存按钮。填写时通过右上角保存；返回箭头退出填写，未保存时保留放弃确认。列表状态的右上角仍为刷新。
- 重复保存相同的详细地址会复用原记录，避免产生重复住处。旧地址、旧名称和坐标不删除；历史名称和坐标仅作为接口兼容数据保留，不展示给用户。新地址的内部名称固定为“常用住处”，坐标为空。
- 旧版账号原有单条文字地址会在首次读取时保留为默认家庭住址。新默认地址同步到旧个人资料 address 字段，以兼容既有展示。
- 保存以服务器事务提交成功为准，成功后刷新本机副本；如果只有本机副本更新失败，会明确提示云端已成功，不会重复提交或假报整次保存失败。
- 本机副本使用账号隔离的 RDB 设置项，离线可查看上次同步的内容；离线不能保存或切换默认。刷新成功后恢复操作。
- 清理缓存不会删除住处，因为住处及本机副本不在 cacheDir/tempDir。注销账号时删除服务器地址和本机地址副本。

## 数据与接口

- `address_service.py`：`t_saved_address` 存在现有账号 SQLite 数据库中，包含 owner、名称、详细地址、经纬度、默认标记、版本和时间。
- `POST /api/addresses/list`、`save`、`default`、`delete` 全部复用现有 Bearer 会话鉴权；归属只取服务端当前会话，忽略客户端提供的用户名。
- 本次简化仅调整客户端表单和入口；保留既有服务端字段及旧接口兼容，当前页面不调用delete，也没有修改现存地址数据。
- 更新、切换默认和删除要求地址 ID 和版本一致；其他账号不能通过猜 ID 读写。唯一索引确保一个账号至多一个默认地址，事务保证列表非空时保有默认地址。
- API 返回 `Cache-Control: no-store`。地址和坐标不写入应用新日志。地图定位、导航、地址真实性验证和地理坐标转换不在本次实现中。
