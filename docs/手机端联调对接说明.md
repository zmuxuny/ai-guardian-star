# 手机端联调对接说明（2026-10-22）

本文是给 HarmonyOS 客户端开发的对接契约。所有内容以仓库 `zy` 分支代码为准（提交 `48628ee`），板端已在候选目录按此验证。

## 一、联调前置条件

| 项目 | 值 / 获取方式 |
| --- | --- |
| 服务地址 | `http://47.108.167.0:6001`（FRP 隧道 → 板内 5000；**必须 http**，无 https） |
| MQTT Broker | `47.108.167.0:8883`，TLS 单向，CA 证书在板端 `/etc/guardian/ca.crt` |
| MQTT 用户名/密码 | 在板端 `/etc/guardian/mqtt.env`（`MQTT_USERNAME` / `MQTT_PASSWORD`），找硬件负责人索取，**不要写进客户端代码仓库** |
| 历史接口令牌 | 板端 `/root/guardian_candidates/20261022T1533-78864b8-rec/.tokens` 的 `HISTORY_TOKEN`，用于下载与查询 |
| 人脸管理令牌 | 同文件 `FACE_ADMIN_TOKEN`，仅 `/api/face/*` 需要 |

> 安全提醒：令牌目前是"联调用临时值"，正式部署时应在板端重新生成并通过安全渠道分发，客户端不要硬编码。

## 二、MQTT 订阅（板子 → 手机）

客户端连上 Broker 后订阅以下主题。所有消息为 UTF-8 JSON，`timestamp` 是服务端本地时间的字符串。

### 1. `ai_guardian/alerts/fall`

```json
{"event": "fall_detected", "timestamp": "2026-10-22 17:00:00.123"}
```

### 2. `ai_guardian/alerts/sit`

```json
{"event": "sit_detected", "timestamp": "...", "duration_seconds": 62.5, "person_id": "3"}
```

### 3. `ai_guardian/alerts/stranger`

```json
{"event": "stranger_detected", "timestamp": "...", "person_id": "3", "score": 0.42}
```

### 4. `ai_guardian/alerts/face`

```json
{"event": "face_recognized", "timestamp": "...", "name": "张三", "score": 0.83, "person_id": "3"}
```

`name` 为 `null` 表示识别中或未识别。

### 5. `ai_guardian/recordings/ready`（新增，视频就绪）

```json
{
  "event": "recording_ready",
  "timestamp": "...",
  "recording_id": "c37430177ade4c43b4e3beb0d2ff9e2d",
  "event_ids": ["5c5e41cbcc724603b1c4f8423a3bc11d"],
  "download_path": "/api/history/recordings/c37430177ade4c43b4e3beb0d2ff9e2d/video"
}
```

**含义**：一段异常视频已经在板内录制完成并缓存。手机收到后**不要立刻下载**，按用户操作（点开详情/点下载）再请求 `download_path`。`event_ids` 是这段视频关联的所有事件。

**时序说明**：先收到 `fall_detected` 等告警（此时视频还在录后录 10 秒），**约 10–20 秒后**才会收到对应片段的 `recording_ready`。客户端应把告警与就绪消息分开处理，用 `event_ids` 关联。

**去重规则**：同一连续行为只报一次（例如持续久坐 1 小时只收到一条 `sit_detected`）；人离开画面再回来会作为新事件重新上报。

## 三、HTTP 接口（手机 → 板子）

所有接口要求请求头 `Authorization: Bearer <HISTORY_TOKEN>`，缺失或错误返回 401。下述路径均相对服务地址。

### 1. 下载视频（核心）

```
GET /api/history/recordings/{recording_id}/video
```

- 成功：`200`，`Content-Type: video/mp4`，可直接喂给播放器（H.264 + MP4 容器，`faststart` 已开启）
- 断点续传：标准 `Range: bytes=...` 请求返回 `206`（Starlette 0.49.3 已含安全修复）
- 错误码：`404` 片段不存在；`503 media_not_ready` 片段尚未完成；`503 media_version_unsupported` 服务端环境不支持（正常部署不会出现）；`422` 非法 ID
- **每次下载会为该片段延长 1 小时"清理租约"**：即使片段已到七天期限，下载中也不会被删除

### 2. 事件列表

```
GET /api/history/events?limit=20&offset=0&kind=sit&start=2026-10-22T00:00:00%2B08:00&end=2026-10-23T00:00:00%2B08:00
```

- `kind` 可选：`fall` / `sit` / `stranger`；`limit` 1–200；`start`/`end` 必须带时区，最大区间 31 天
- 返回 `{"items": [...], "limit": 20, "offset": 0}`，按开始时间倒序

### 3. 事件详情（含关联视频）

```
GET /api/history/events/{event_id}
```

返回中 `"recordings": [...]` 是该事件关联的片段列表，每项含 `id`、`state`（`complete` 才可下载）、`size_bytes`、`started_at`、`ended_at`。用其中的 `id` 拼下载地址。

### 4. 录像列表

```
GET /api/history/recordings?limit=50
```

### 5. 服务状态

```
GET /api/history/status
```

`media_download_enabled=true` 表示下载可用；`resume_verified=false` 表示断点续传尚未做端到端弱网验证。

## 四、建议的客户端行为

1. 收到告警 → 本地通知（同告警 5–30 秒内有服务端节流，客户端无需再去重）
2. 收到 `recording_ready` → 在事件详情页展示"有视频"角标
3. 用户点开 → 按 `recording_id` 下载 → 边下边播或下载后播放（H.264/MP4 均为 HarmonyOS 原生支持格式）
4. 明确不走"自动上传到云"——视频只在板内存七天，过期由板端自动清理，客户端 404 时提示"视频已过保留期"
5. 网络配置：当前是明文 HTTP，HarmonyOS 需在应用网络配置中允许 cleartext 流量到 `47.108.167.0`

## 五、联调步骤（建议顺序）

1. 客户端先打通 MQTT：订阅全部五个主题，站在镜头前等陌生人事件（测试环境人脸库为空，任何入镜人脸都会触发），核对 JSON 能解析
2. 打通下载：收到 `recording_ready` 后直接 curl/HTTP 请求下载，确认能拿到 MP4 且可播放
3. 打通列表与详情：拉事件列表 → 进详情 → 用 `recordings[].id` 下载
4. 联调异常路径：不带令牌（应 401）、错误令牌（401）、不存在的 ID（404）、刚触发就下载（503 media_not_ready，等 20 秒重试）
5. 真实场景：摔倒动作 → 观察 `fall_detected` → `recording_ready` → 下载回放，画面应带检测框与状态文字

## 六、已知边界（联调时不要误判为 bug）

- 告警与 `recording_ready` 之间有 10–20 秒延迟是设计行为（后录 10 秒必须录完）
- 下载需 `state=complete`；刚收到 MQTT 就立刻下载可能撞上 `media_not_ready`，等几秒重试即可
- 服务端对重复参数、未知参数、非法时间区间一律 422，错误响应不回显输入
- 测试窗口内 `/api/face/*` 需要 `X-Admin-Token`，手机端旧版人脸功能会 401，这是预期（正式部署前需客户端适配）
