# 2026-10-25 人脸图库多尺度特征优化

## 背景

开发板接入真实 USB 摄像头后，登记人员在正脸、轻微侧脸、低头和局部遮挡之间切换时，ArcFace 分数波动明显。原实现只对每张登记照片生成一个特征，登记图的人脸留白比例与实时检测框不一致时，熟人可能长期停留在 `pending`，最后因超时暂列陌生人。

用户确认 `Hjb` 与原登记名 `周阳` 是两个不同身份，并要求将后者的显示名改为 `zy`。本轮保留 `Hjb`，将用户 ID `zhouyang` 对应的数据库名称和图库目录原子迁移为 `zy`，原照片不变。

## 修改前证据

- 开发板：Orange Pi AI Pro / Ascend 310B4 / CANN 7.0.0。
- 正式服务、摄像头和 MQTT 均在线，实时推理约 6～7 fps。
- 图库包含 3 张实际照片、2 个独立身份：`Hjb` 两张，`zy` 一张。
- 相机前存在明显遮挡时，实时样本分数约为 `0.248～0.320`；画面完整时，原图库特征对同一组样本的分数可达到 `0.473`、`0.704`、`0.523`、`0.502`。
- 将登记照片临时按人脸框保留 30% 或 45% 留白后，部分样本由 `0.473→0.610`、`0.523→0.557`、`0.502→0.546`。严重截断样本仍低于 `0.45`，没有通过降低门槛获得姓名。
- 以上身份名称来自用户登记和用户确认；诊断不根据外观推断真实身份。

## 实现

代码提交：`dfe7763127a27f189cbf81a278ca129a423aafba`。

修改 `src/ascend_main_other.py`：

1. ArcFace 图库加载时继续保留登记照片的原始特征。
2. 使用项目已有 OpenCV Haar 检测器选取面积最大的人脸，并在内存中增加 30% 与 45% 留白的两个特征。
3. 多尺度特征只存在于运行内存，不生成派生照片，不修改 SQLite 表结构，不改变 API `photo_count`。
4. OpenCV 检测器不可用、没有检测到人脸或生成裁剪异常时，退回原始照片特征。
5. 保留 ArcFace 匹配门槛 `0.45`、身份差距 `0.08`、陌生人投票、质量门和识别超时规则。
6. ArcFace 模型失效时仍整库回退到同一 CPU 特征空间，避免混用不同维度。

修改 `tests/test_face_recognition.py`：

- 新增回归测试：一张登记照片仍计数为 1，但内存中的裁剪变体能够命中姓名。
- 测试先在旧实现上以 `entries=1` 失败，修改后变为 `entries=2` 并识别 `known:Yang`。
