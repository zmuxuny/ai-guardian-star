# 2026-10-22：异常行为触发录像缓存

## 问题与修改原因

`f02124f` 只提供了录像**骨架**：`RecordingManager` 会连续分段录制，`HistoryStore` 能记事件，但两者互不认识——`recordings` 表没有任何字段指向事件，也没有"检测到异常才保存一段视频"的逻辑。实际需求是：摔倒/久坐/陌生人等异常发生时，自动保存一段**包含事件发生前若干秒**的视频，并能在事件详情里查到对应片段。

前置结论来自同日的板端清点：`recordings` 表字段为 `id/relpath/started_at/ended_at/size_bytes/state/error/metadata/lease_until`，`has_event_column=false`，确认该功能当时**并未实现**。

| `src/guardian_event_cache.py` | 新增。预录环形缓冲 + 触发录制 + 事件关联，复用 `RecordingManager` 作为写入器 |

## 行为变化

- 默认配置仍为**关闭**（`enabled=False`），不建目录、不起线程、不占内存。
- 开启后：摄像头采集点调用 `submit_frame` 只做有界内存复制；空闲时保留最近 `pre_roll_seconds` 的帧（帧数上限 `ceil(pre_roll × record_fps) + 2`，字节上限 `cache_bytes`）。
- `trigger()` 写入事件行，把预录窗口内的帧快照进片段队列，并设定 `now + post_roll_seconds` 为结束时间；同一片段内重复触发只延长时间、追加事件，不改文件，且总时长不超过 `event_clip_max_seconds`（超出时 `capped=true`）。
- 到期后由 `RecordingManager` 完成封装与 `media_verified` 校验，再写入 `event_recordings` 关联。
- 一个事件片段对应**一条** `recordings` 记录，一个片段可关联**多个**事件。

**未接入的部分（有意保留）**：本提交没有修改 `src/ascend_board_server.py`、`src/ascend_main_other.py`。这两个文件工作区存在他人未提交的 ACL 改动，混入会破坏可回退性；采集与告警的接线单独进行，见实现说明的"接入步骤"。

## 验证结果

**本地（Windows，Python 3.14.6 + NumPy 2.5.2）**：`python -m unittest discover -s tests` → 130 项通过、1 项跳过、0 失败。跳过项为 `test_history_api` 整模块（本机缺 FastAPI/httpx）。

**板端（Orange Pi Ai Pro，生产 venv Python 3.9.2 / NumPy 2.0.2 / OpenCV 4.13.0 / SQLite 3.40.1，候选目录 `/root/guardian_candidates/20261022T1533-78864b8-rec`）**：

- 全量测试 141 项通过、0 跳过、0 失败（把 `httpx==0.28.1` 隔离安装到候选 `test_deps` 后用 `PYTHONPATH` 引入，未改动生产 venv）。
- 真实 ffmpeg 4.4.2 + libx264 端到端：`pre_roll_seconds=2`、`post_roll_seconds=1`、10 fps、640×480。
  - 空闲期缓存 20 帧；触发时预录快照 19 帧；触发后提交 12 帧；`accepted_total=32`，丢帧 0。
  - 片段：`written_frames=30`、`state=complete`、`media_verified=true`、`size_bytes=3785`，`ffprobe` 确认 `h264 / 640x480 / 30 帧 / 3.0 秒`。
  - `linked_recordings=1`，`last_clip.linked_events=1`。
  - **关键判据**：触发后只提交了 12 帧，而片段内有 30 帧，说明触发前的预录帧确实进入了同一片段（`pre_roll_included=true`）。
- 生产零影响：`guardian-board.service` 仍 `active`，MainPID 26541 未变；生产源码 `sha256sum -c` 全部一致。
