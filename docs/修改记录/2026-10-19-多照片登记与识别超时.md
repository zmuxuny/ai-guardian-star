## 1. 照片数量只提示，不设最少或最多张数

同一 `user_id`、同一姓名继续调用原 `POST /api/face/enroll` 时追加保存照片，不再删除上一次照片。一张有效照片就可以登记，追加更多照片不受张数门槛限制；沿用原单文件非空、8 MiB 大小、图片解码和分辨率检查，不限制张数不代表取消单文件检查。

页面与接口提示：**上传不同方向的照片，有助于加快识别并提高精度；照片数量不作要求，一张也可登记。**

“加快”指有机会减少反复等待匹配的次数，不是单次模型推理必然更快，也不是准确率保证。较大图库会增加重载、存储与匹配开销；效果需板端对照。照片仍通过已有图库按目录姓名建特征，不新增模型、数据库表或部署依赖。

`enroll` 保留原字段，增加 `photo_count` 和 `hint`；`/api/face/list` 在各人员记录中增加 `photo_count`，响应增加 `hint`。计数只统计此用户由 API 命名的照片，不统计手工管理的其他图片；SQLite 原单行记录保留最新上传图片字节及登记时间，多个样本保存在原图片目录。原 `recognition_status` 含义保留。

同一用户改名时，将该用户旧照片迁入新姓名目录并追加新照片。搬移失败或数据库写入失败时回退已搬移文件，删除本次新文件；追加失败不会删掉原照片。删除用户时删除该用户全部 API 照片，数据库删除失败时恢复临时移动的照片。

文件归属根据完整用户 ID 和合法后缀判断，解决 `user` 与 `user_a` 前缀重叠时可能相互误删的问题。兼容当前 `<user_id>_<32位UUID>.jpg`，并对照 9 月备份确认支持旧 `<user_id>_<时间戳>.jpg`。旧手工图片仍可参与图库匹配，但不自动归属于某个 API 用户的计数/删除；同名目录合并为同一识别姓名的旧行为也保留。

保留 API 路由、管理员鉴权、JPG 格式、SQLite 表及原字段，但**重复上传从替换改为追加**是本轮有意的行为变化。更新旧照片需先删除该用户再重新登记；现阶段不提供单张样本删除界面。异常进程退出、磁盘故障或多进程并发写入的文件/数据库一致性仍不是原子事务，本轮只覆盖正常请求内的失败回退。

## 2. 根据人数和画面情况设置有界超时

从当前人体轨迹首次出现开始计时。正常匹配成功立即显示姓名；明确不匹配仍可按既有三票规则提前显示陌生人。尚未确定身份的轨迹采用以下默认上限：

`等待秒数 = min(60, 20 + 4 × (当前可见人数 - 1) + 画面质量补偿)`

- 单人正常画面：20 秒。
- 每增加一位可见人员：增加 4 秒，给现有全局四秒识别冷却留出轮转时间。
- 过暗、弱光、过曝、模糊、细节不足、关键点不可用或没有可用人脸：再增加 10 秒。
- 最长 60 秒；等待中的期限可以因拥挤或画质变差延长，不会因为人员减少或画质改善突然缩短。

这些是结合现有调度设置的初值，没有真实板端耗时证据，后续应校准。人数与画面补偿不意味着保证每个人在上限内完成足够识别次数。

计时在当前可见人物的推理结果构建阶段检查，独立于“有无成功调用识别模型”。因此严重遮挡、持续弱光、图库加载失败或模型不可用时，仍按用户要求在超时后显示“陌生人”，副标题明确为 **“识别超时，暂列陌生人”**，分数为空。它说明未能及时确认身份，不能作为确实没有登记照片的证据；熟人也可能因画质差而超时。

超时检查发生在该帧尝试识别之后：最后一次机会匹配成功时以姓名为准。一旦超时，不会因为随后人数增加或画质改变而重新延长期限，超时原因与空分数持续保留，直到新身份窗口或成功识别。超时不锁死身份，后续保持既有八秒重试，成功后可以恢复姓名并清除超时标志。CPU 已知候选仍需既有两票确认，只有一票时暂时保留超时陌生人。

已确认姓名不会仅因在场时间长而到期；若后续有效匹配不再确认姓名，或无专用人脸检测器时丢失关键点导致回到等待，则开始新的等待窗口，避免拿很久以前的首次出现时间立即判超时。图库版本变化也重新开始等待；弱人体关联清空旧身份，未识别状态不会每帧刷新等待起点。原轨迹过期与新轨迹仍沿用原跟踪逻辑。

监控 `faces` 数组增加 `wait_seconds`、`timeout_seconds`；等待页面显示经过时间与当前阈值。`reason=timeout` 与原 `unmatched` 区分超时和匹配证据。超时使用已有 `stranger` 标签，因此也会进入既有陌生人统计、MQTT/事件链路；它不是只改页面文字。

计时依赖正常的持续推理更新，不在摄像头离线或推理停止时凭空生成新人物告警；程序卡住时也无法承诺严格的墙钟截止。暂停、断连、遮挡导致轨迹消失后，是否重新计时取决于原跟踪是否分配新 ID。

| 环境变量 | 默认 | 有效范围 |

| `AI_GUARDIAN_FACE_WAIT_SECONDS` | 20 秒 | 8～300 秒 |
