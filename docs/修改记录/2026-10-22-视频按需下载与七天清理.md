# 2026-10-22：视频按需下载与七天清理

## 问题与修改原因

用户定义的产品闭环：**异常视频先缓存在板内 → 提醒手机 → 手机需要时再下载 → 视频只留七天**。对照当时状态：①板内缓存已完成；②MQTT 告警只有文字、不带视频引用，且告警发出时片段还在录（后录 10 秒）；③下载接口固定 503；④清理逻辑写好了但从未被调度。本轮补齐 ②③④。

## 影响文件

| 文件 | 变化 |
| --- | --- |
| `src/guardian_history_api.py` | `/recordings/{id}/video` 从固定 503 改为真实下载：Bearer 鉴权 → 仅 `state='complete'` → `safe_managed_path` 校验路径 → **延长清理租约** → `FileResponse`（按已装 Starlette 版本决定是否放行，0.49.3 支持 Range）；`media_download_enabled` 状态字段改为按版本报告 |
| `src/guardian_history.py` | 新增 `lease_recording(id, seconds)`：下载时把 `lease_until` 推到未来，`cleanup_expired` 会跳过未到期租约，正在下载的文件不会被清掉 |
| `src/guardian_cleanup.py` | 新增 `CleanupScheduler` 周期调度 + `system_clock_trusted()`（年份合理且 `timedatectl` 报告 NTP 同步才可信）。**时钟不可信时清理只记 skip、绝不删文件** |
| `src/guardian_event_cache.py` | 片段封装并完成事件关联后触发 `on_clip_ready(event_ids, recording_id)` 回调 |
| `src/ascend_main_other.py` | `MQTTAlertClient.publish_record_ready()`：向新主题 `ai_guardian/recordings/ready` 发布 `{recording_id, event_ids, download_path}` |
| `src/ascend_board_server.py` | 注册历史路由（**此前从未挂载**，见下）、启动/停止清理调度、把 MQTT 客户端接入回调 |
| `tests/test_history_api.py` 等 | 更新媒体端点断言，新增下载/租约/调度/回调测试 |

## 关键发现：历史路由从未被注册

接线验证时下载返回 FastAPI 默认 404（`{"detail":"Not Found"}`），而非接口自定义错误——排查发现 `create_history_router()` 自设计以来**从未在 `ascend_board_server.py` 中调用**，此前所有接口验证都是直接对 router 对象做的，掩盖了这一点。本轮在录像启用分支里 `app.include_router(...)` 补上。教训：对 router 的单测无法发现"路由没挂载"这类集成缺陷。

## 行为变化

- 手机收到 MQTT `recording_ready`（含 `recording_id` 与 `download_path`）后，带 `Authorization: Bearer <AI_GUARDIAN_HISTORY_TOKEN>` 请求 `/api/history/recordings/{id}/video` 即可下载。
- 每次下载把该片段的清理租约延长 1 小时；七天到期但租约未到期的片段不会被删除。
- 清理调度随录像生命周期启停；时钟不可信（无 NTP、年份异常）时跳过删除并在日志/状态中可见。

## 验证结果

- **本地**：159 项测试全部通过（含 15 项接口测试；本机以 `--target` 隔离安装 FastAPI/httpx 后不再跳过）。
- **板端**（生产 venv，候选目录 `20261022T1533-78864b8-rec`）：159 项通过、0 跳过。
- **端到端**：服务自动触发久坐/陌生人事件 → 片段落盘 → 日志出现 `[MQTT] Recording Ready Sent: <id>` → `curl -H "Authorization: Bearer ..."` 下载 **HTTP 200，与磁盘文件逐字节一致** → 下载后该片段 `lease_until` 已延长 → `/api/history/status` 报告 `media_download_enabled: true`、`file_response_range: version_capable_unverified`、`resume_verified: false`。
- 板端时钟：`system_clock_trusted()` 返回 True（NTP 已同步），清理调度具备执行条件；当前片段均为新片段，无过期可删，真实"第八天删除"由单测覆盖（时间边界已验证）。

## 待验证事项

- 手机端真实联调：MQTT 消息格式需与客户端约定；客户端需要拿到 `AI_GUARDIAN_HISTORY_TOKEN`（部署时的令牌分发问题）。
- 断点续传（Range 206）本地与接口测试已过，真实弱网环境未测。
- 下载与清理并发竞争：租约机制已覆盖，但"下载中进程重启"的边界未测。
- 正式部署到 `/root/ai_guardian` 仍需先解决人脸接口 `X-Admin-Token` 的客户端适配。

## 部署与回退

部署即接线流程：备份 → 部署 `zy` → 设置 `AI_GUARDIAN_RECORDING_CONFIG` 与 `AI_GUARDIAN_HISTORY_TOKEN` → 重启 → 确认日志出现"历史查询接口已注册"与"七天清理调度已启动"。回退：删除环境变量重启即回到关闭态；`git revert cb0ec7b` 撤销代码。
