## 改动与原因

### 1. 修复检测分数和裁剪质量分数的门槛冲突

旧流程获得有效人脸检测框后，把检测器的概率分数当作裁剪质量分数，再与 `FACE_RECOG_MIN_QUALITY_SCORE=1.05` 比较。对于通常处于 0～1 的检测分数，这个条件无法通过，也不会重新进入姿态裁剪分支；可能出现检测到人脸却持续等待的情况。

现在分别判断两个来源：

- 人脸检测框：继续使用 `FACE_RECOG_MIN_FACEDET_SCORE=0.55`，要求分数有限、裁剪非空且宽高至少 24 像素。
- 姿态头部裁剪：继续使用原来的 `0.80` 最低裁剪分数、`1.05` 质量分数和正脸条件。
- 最佳裁剪缓存统一比较 `score_face_crop` 的质量分数，避免概率分数与质量分数混用。

例如，检测分数 0.90、裁剪有效，但姿态头部关键点不足时，旧流程会被 `1.05` 门槛挡住；新流程会进入识别。最终能否返回熟人仍由特征匹配阈值决定，不能将“进入识别”视为“识别正确”。

### 2. ArcFace 实时识别跳过不使用的 CPU 处理

旧流程即使使用 ACL 人脸特征，也会先执行灰度提取和 Haar 检测，再把原彩色裁剪送给 ArcFace，前面的 CPU 结果未用于该次匹配。

现在仅 CPU 后备分支准备灰度、Haar 和 LBPH 数据。ArcFace 分支继续使用原彩色输入；登记库仍保留原有后备准备流程。减少了无效工作，但实际耗时变化需用板端 `[Perf]` 日志确认。

### 3. 返回姓名与得分来自同一匹配样本

旧实现先得到最佳样本姓名与分数，之后又用最佳身份中心覆盖姓名，最后却按最佳样本分数和差距决定是否接受。两者不同时，可能返回另一个人的名字。

现在接受条件与返回姓名都使用最佳样本；中心仍保留用于诊断和身份数量统计。原相似度与差距阈值不变。

### 4. 模型输出校验与一致的 CPU 降级

- 空、NaN、Infinity、近零范数的 ACL 输出不能作为有效特征；沿用原布局尝试和失败后停用 ACL 识别器的流程。
- 加载库期间 ACL 识别失败时，重新用 CPU 特征建立完整候选库，避免同库混入不同维度的特征。
- 运行中 ACL 识别器停用时，先完整重建 CPU 库，再用同一种 CPU 特征匹配。库重建失败返回 `("unknown", None)`，保留旧库并记录日志。
- 找不到同维度特征时返回无有效分数，不使用 `999` 一类距离哨兵作为“确认陌生人”的证据。
- CPU 库和实时特征统一使用原有灰度特征函数；灰度提取失败的样本跳过或返回未知，不再切换到维度不同的彩色图特征函数，避免原 2336/2912 维特征混用。

CPU 后备保留已有灰度特征、LBPH 可选路径及距离阈值。ArcFace 的“相似度越高越好”强匹配快捷条件仅用于 ArcFace；CPU/LBPH 距离不再与 `0.45` 相似度比较，使用原配置要求的至少两次熟人投票。CPU 分支可能因此比旧版一票接受多等待一个识别周期；后备算法与 ArcFace 的准确率不能视为等价，切换后的实际表现需单独实测。

### 5. 完整发布人脸库并失效旧身份缓存

加载时在独立候选对象中构建完整库，再持锁一次性发布；读者可在构建期间继续使用完整旧库。构建失败不会留下空库或半个库。串行加载锁与读取状态锁分开，CPU 降级重建在释放读取锁后进行。

每次成功发布增加库版本。推理检测到版本变化后清除人脸标签、得分、投票、最佳裁剪和近期熟人复用缓存，保留人体框、摔倒和静止状态。匹配期间库被替换时，旧版本的匹配结果不写回人物状态。

兼容现有 HTTP 行为：人脸录入/删除接口、SQLite 表、图片目录和图片格式沿用既有实现。接口仍通过原 `load()` 调用重载，没有引入新的硬件线程或 ACL context。成功重载后旧身份在后续推理中失效；重载失败仍需根据日志重试，落盘数据与旧识别库可能暂时不同步。

## 保留的兼容约定

- 模型候选路径和优先顺序、`USE_ARCFACE_ON_BOARD` 设置。
- ArcFace 112×112、BGR→RGB、`(rgb - 127.5) / 128.0`、float32、原有 NCHW/NHWC 首选与后备逻辑。
- 相似度 `0.45`、差距 `0.08`、投票窗口与最低票数、识别冷却 3 秒、全局冷却 4 秒、未知重试 8 秒等配置。
- `FaceLibrary(library_dir, recognizer)`、`load()`、`recognize(image)` 的调用方式；识别结果仍为 `(label, score)`，保留 `known:*`、`unknown`、`unregistered`。
- ACL 全局推理锁、模型所有权和现有服务启动链路。
- `requirements-edge.txt` 无新增运行依赖；OpenCV 的 LBPH 仍为可选能力。

本轮没有宣称旧参数是最佳参数。板端对比样本证据充分时，再按误识率和漏识率调整参数并单独记录。
