## 身份规则

| 场景 | 行为 |
| --- | --- |
| 登记照片有效，实时特征满足对应后端的既有接受规则 | 显示登记姓名；ArcFace 保留原强匹配快捷接受，CPU 保留至少两票 |
| 获取有效人脸与有效分数，但未达到登记身份的匹配门槛 | 最近四次有效结果中至少三次明确不匹配，且人物出现至少两秒后，显示“陌生人” |
| 已成功加载且确实没有任何登记图片 | 有效人脸产生“未登记”证据，按同一三票与两秒条件显示“陌生人” |
| 人脸裁剪不可用、模型没有输出、分数异常、图库尚未加载 | 不累计陌生人证据；新人物显示“等待识别” |
| 有上传图片但全部不可用，或图库重载失败 | 显示等待并输出诊断，不能把故障当成无人登记 |
| 最高分看似匹配但不同登记身份差距不足，或分数恰好落在边界 | 不直接定为陌生人，继续等待更明确结果 |
| 已有姓名后来出现有效但未确认身份的结果 | 清除姓名，进入等待；累计足够明确不匹配后变为陌生人；重新匹配可恢复姓名 |

对于已经确认的标签，单次无效模型结果保持原状态；已确认陌生人遇到含糊结果也保持陌生人。强人体连续跟踪可暂时保留已验证姓名，弱关联或新轨迹会清空姓名，随后重新识别。上述保留不是新的身份认证证据。

三票不是三帧，也不保证两秒内完成识别。沿用单人三秒重试、全局四秒冷却；顺利连续取得三个结果通常至少跨越八秒，多人、低质量画面或模型耗时会进一步延长。已识别人员和陌生人沿用八秒复查间隔；人物离开、遮挡与轨迹变化会影响实际时序。

## 修改内容与原因

### 1. 消除明确不匹配却长期等待的区间

旧单身份 ArcFace 的陌生人阈值是 `0.05`，熟人接受阈值为 `0.45`，使 `0.05～0.45` 的不匹配结果可能一直等待。CPU 同样存在 `0.62～0.74` 的间隙。

- 单身份 ArcFace 的陌生人门槛改为引用既有熟人门槛 `0.45`，多身份门槛仍为 `0.45`；明确陌生人证据使用严格小于。
- CPU 陌生人距离门槛改为引用既有 `0.62`；明确陌生人证据使用严格大于。
- `0.45` 相似度和 `0.62` 距离边界处，是否接受姓名仍由现有匹配函数决定。若函数因差距不足返回未知，该边界不算陌生人票。
- 按图库实际使用的 ArcFace/CPU 后端解释分数，避免模型启用标志与降级后的图库不一致。
- 合法负余弦相似度可作为不匹配证据；缺失、NaN、Infinity 和哨兵分数不能投票。CPU 未知分数限定在归一化特征欧氏距离范围内，LBPH 的已知结果保留原距离格式。

熟人匹配阈值、ArcFace 身份差距 `0.08`、CPU 特征距离差距 `0.10`、四票窗口、最低三票陌生人和两秒最小轨迹年龄保留。可选 LBPH 快捷匹配仍使用距离 `<65`，不检查这两个差距；CPU/LBPH 的已知结果仍需至少两票确认。此处调整陌生人判定区间，不以降低熟人门槛掩盖漏识别。

### 2. 区分空图库与故障图库

`FaceLibrary` 新增登记样本数与重载失败状态。扫描到支持扩展名的图片即计数，解码失败或小于 24 像素的图片跳过，但仍可判断“有图片、无可用样本”。

重载成功完整发布候选库，并清除故障状态。重载异常保留旧库对象以避免半库，同时标记不可识别并递增版本；失败后不能继续用旧登记身份匹配。后续推理检测版本变化会清除旧姓名与投票，保留人体与摔倒状态。必须再次成功重载或修复后重启才能恢复识别。

构建候选库期间，读者仍可读取完整旧快照；删除/更新后的旧身份会在库版本同步及下一次推理后失效，不承诺 API 响应瞬间所有画面同步。

### 3. 身体位置不能替代人脸认证

新轨迹不再调用近期或活跃熟人的几何恢复逻辑来继承姓名；弱人体关联同时清除熟人、陌生人、投票和最佳裁剪。强关联可暂时沿用上次已验证姓名。

已知身份也定期复查，解决旧姓名一直保留的问题。每次处理按上次识别时间从早到晚尝试，优先照顾从未识别或等待最久的人，防止已有姓名的人一直占用全局识别机会；输出告警仍保持原人体顺序。

### 4. 上传/删除接口说明图库是否更新

保留 `ok`、`user_id`、`name`、`deleted` 和现有状态码、鉴权方式，额外返回 `recognition_status`：

| 值 | 含义 |
| --- | --- |
| `ready` | 重载成功；上传时该图片已进入可用样本列表。不是实际人脸或识别准确率认证 |
| `photo_unusable` | 图片已保存，但未进入可用样本列表，需要检查图片与模型诊断 |
| `reload_failed` | 图片/数据库操作已完成，图库重载异常，需要修复并重新加载 |
| `service_offline` | 推理对象不存在或没有人脸库，暂未执行图库加载 |

`ok: true` 继续表示存储操作成功；客户端若需要区分识别是否就绪，应读取新增状态。没有强制改变现有客户端。照片仍保存到原 `known_faces/<name>` 路径，SQLite 表和 JPG 格式不变；手工维护的旧照片目录仍兼容，登记来源不是只读数据库。返回 `service_offline` 后需等待后续成功加载。

这些状态只说明本次图库重载，不是服务健康检查。推理对象创建后、初始化尚未完成的启动窗口内，接口仍可能执行重载；`ready` 不保证摄像头、模型初始化或完整服务已经运行，此行为仍沿用旧同步重载路径，需在板端检查。

### 5. 页面显示

监控页面保留等待状态的人员，避免有检测对象却显示“无检测对象”；已知人员副标题改为“已登记人员”，分数标题改为“匹配分数”。空图库的陌生人没有数值分数，显示 `--`。相似度与距离不作为统一概率或百分比。
