# AI 使用权限

## 三档共享范围

| 模式 | 自动附带给云端模型的监护数据 |
| --- | --- |
| 基础问答 basic | 无 |
| 隐私保护 privacy（默认数据范围） | 近7天摔倒次数、久坐次数、距最近摔倒天数、设备在线状态 |
| 深度照护 full | 上述统计，加设备连接状态、当前监护消息、最近摔倒和久坐的精确日期时间 |

本定义沿用此前权限选择器的数据范围。项目旧笔记中“privacy 不送健康统计”与实际功能不一致，以本文和接口校验为准。深度照护不代表完整历史病历，也不会自动上传视频、录像、人脸、姓名、地址或经纬度。

## 用户操作

个人中心 → AI 健康助手开关 / AI 分析权限。初次升级没有云端授权记录时，AI 保持关闭、数据范围为隐私保护；需用户手动开启。旧本机授权不自动升级为云端授权。

设置提交期间禁止重复操作和新问题发送。云端确认保存后更新页面；失败显示原因并重新读取实际云端设置；无法联网确认时保持不可发送。数据范围可在 AI 关闭时设置。切换权限会清空当前对话和输入框，丢弃在途回复。

## 隐私边界

- 问题、最近最多20条对话会经 HTTPS 发送至应用服务器；通过内容安全审核后再发送云端模型。历史总计最多16000字符，单条最多2000字符。
- 客户端及服务器都隐藏常见大陆手机号、18位身份证号和邮箱；服务器同时处理当前监护消息、历史和返回文本。
- 规则匹配无法识别所有变体，不能保证隐藏人名、家庭地址或所有身份信息。用户仍应避免输入这些内容。“隐私保护”表示共享较少的监护字段，不表示完全匿名或本地运行。
- App 不将对话正文写入业务数据库；此次未验证第三方供应商的留存或训练政策，不承诺外部服务零留存。
- 关闭和撤销授权不能收回已经发送给外部服务的数据。服务端在提交模型前和回复返回前重新检查权限；已开始的外部计算无法保证即时终止，权限变化后的结果不再显示。

## 接口和实现

- POST `/api/ai/settings/read`：返回 `settings: {enabled, accessLevel, version}`。新账号默认为关闭/privacy/version0，不创建授权行。
- POST `/api/ai/settings/save`：要求同结构，version为读到的版本；由认证会话确定账号，忽略请求体中的账号。事务更新并增加版本，过期写入409；保存错误500且不提示成功。
- POST `/ai/chat`：必须提供当前 `policyVersion` 和与云端相同的 `context.accessLevel`；未开启403、版本或等级不一致409、非法字段400、超长输入413。旧客户端不会继续使用本机授权越过云端校验。
- 服务端 SQLite 表 `t_ai_permission`，账号删除自动清理，账号更名同步。没有将健康详情存进授权表。相关响应使用 private/no-store。
- `AiPermissionService.ets` 负责同步及确认后的共享状态；本地旧 `t_setting` AI 设置不再作为授权依据。退出、切换账号和同步失败均拒绝复用旧授权。
- `WenxinService.ets` 再次检查开关、同步最新权限、裁剪和脱敏。`AiChat.ets` 监听授权变化并丢弃旧请求的页面更新。服务端 `ai_permissions.py` 白名单验证及脱敏；`wenxin_proxy.py` 对整个待发送提示和模型回复分别审核。
