# 开发板摄像头恢复补丁

适用于 `camera-recovery-sha256.json` 中的两份已核验板端源码。完整源码含部署私密配置，不进入 Git；仓库仅保存最小补丁。

行为：NPU 初始化成功后，即使摄像头缺失也保留推理服务；采集线程每 3 秒重新扫描摄像头。读取失败立即清空待处理帧，释放摄像头后重连。停止服务会唤醒重试等待，不再重新打开摄像头。

`/api/stats` 增加 `camera_connected`。超过 3 秒没有采集帧或输出画面，FPS 显示 0，状态显示摄像头离线或等待新画面；`/video_frame` 返回 204，`/video_feed` 暂停发送。重新接入后，旧摄像头会话的缓存不得作为新画面返回。现有模型、检测阈值与校准参数保持不变。

## 部署

先停止 `guardian-board`，保留现有部署回滚备份。将本目录的 patch、SHA-256 JSON 和 Python 应用脚本放到同一目录，在板端运行：

```text
python3 camera-recovery-apply.py /实际板端源码目录 --check
python3 camera-recovery-apply.py /实际板端源码目录
```

脚本依赖系统 `patch`。先核对原件 SHA-256，在临时目录应用补丁，确认结果 SHA-256 和 Python 语法，再保留 `.camera-before` 备份并写回。再次执行仅核验已应用状态；文件漂移或部分应用会拒绝操作。完成后由部署人员重新启动服务并验收，不由脚本自动重启。

## 回归与设备验收

```powershell
$env:BOARD_CAMERA_SOURCE='完整板端源码副本目录'
python -m unittest test_board_camera_recovery -v
```

测试使用 AST 提取真实方法、隔离 NPU 和摄像头，覆盖缺摄像头启动、后接入、读失败重连、停止重试、清空缓存、过期采集帧、过期输出、跨重连旧帧和正常输出。未提供源码时明确跳过，不把跳过当通过。

这些测试不能代替 USB 驱动与设备验收。部署后需观察帧数持续增加；缺摄像头启动后接入，以及拔插后恢复，均应在原进程中完成。驱动若永久阻塞原生 `read()`，API 会在 3 秒后标记过期，但 Python 无法强制中断该原生调用；需进一步诊断驱动或隔离采集进程。
